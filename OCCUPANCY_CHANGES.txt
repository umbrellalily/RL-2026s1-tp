원칙: 기존 파일은 일절 수정하지 않음. 전부 "새 파일"로 추가(상속 + 래퍼).

[배경 — 왜 이 변경을 했나]
--------------------------------------------------------------------------------
demo_strict_91.gif: 형태 "D" 형성 중 14칸 중 5칸만 채우고, 나머지 드론은
빈 타깃칸의 "정확히 한 칸 옆/아래"에서 step ~100부터 500(timeout)까지 미동도
안 함. 충돌이 아니라 교착(deadlock) + 얼어붙음(freeze)으로 인한 실패.

핵심 정보 결함:
  드론의 관측(obs)에는 "어느 타깃칸이 비었는지"가 직접 들어있지 않다.
  - 들어있는 것: 자기 위치, 모든 타깃칸 좌표, 다른 드론들의 위치(단, comm_fail로
    드롭될 수 있음), 자기 배정칸 좌표 (+배터리).
  - 점유 여부는 "다른 드론 위치"로 간접 추론해야 하고, 통신 두절 시엔 그조차 사라짐.
  => 빈칸 바로 앞 드론도 "이 칸이 비었으니 들어가면 이득"이라는 깨끗한 신호가 없어
     'stay' 국소최적에 안주 → 완성 실패.

해결 아이디어(강화학습의 의미를 지키는 방향):
  답(어느 칸으로 갈지)을 고전 알고리즘으로 떠먹여 주는 "동적 재배정" 대신,
  정책이 스스로 판단하도록 "어느 칸이 비었는지"라는 관측 정보를 추가한다.
  => 배정/라우팅 판단은 학습된 정책 안에 그대로 남는다.

[무엇을 추가했나 — 관측 확장]
--------------------------------------------------------------------------------
각 드론 관측의 "끝"에 타깃칸 점유 벡터를 덧붙임:
    occupancy[i] = 1.0  (target_cells[i]에 드론이 하나라도 있으면)
                 = 0.0  (비어 있으면)
    순서는 env.target_cells와 동일, 길이 = n_agents (모든 포메이션은 정확히
    n_agents개 칸을 가짐).
기존 관측 항목의 위치는 그대로 두고 "맨 뒤"에만 추가 → 해석 명확.
결과: obs_dim 이 n_agents 만큼 증가 (예: 14대 배터리 환경 85 -> 99).

[설계 선택]
--------------------------------------------------------------------------------
1) GLOBAL 신호: 점유 벡터는 모든 드론에게 항상 보이며 comm_fail_prob의 영향을
   받지 않음(지상국이 "현재 채워진 슬롯"을 방송한다고 해석). 목적이 "정책에
   부족했던 조정 정보를 주는 것"이라 의도적으로 전역 신호로 둠.
   - 대안(미채택): comm-fail 반영 점유 — 점유 드론과 링크가 살아있는 경우에만
     1로 카운트. 통신 robustness를 더 빡세게 보고 싶으면 이 변형을 고려.
2) obs_dim 변경 => 비-점유로 학습된 ckpt와 가중치 호환 불가. 점유 정책은
   "처음부터 재학습" 필요.
3) 보상/배터리 로직은 전혀 안 건드림(상속). 관측만 확장.

[추가한 파일 — 기존 파일 미수정]
--------------------------------------------------------------------------------
1) comm_env_occupancy.py
   - OccupancyShapeFormationEnv(ShapeFormationEnv)          : 배터리 없는 점유 env
   - BatteryOccupancyShapeFormationEnv(BatteryShapeFormationEnv): 배터리 점유 env
   - 각 클래스는 __init__에서 super().__init__ 후 obs_dim += n_agents 및
     observation Box 재생성, _get_obs에서 super()._get_obs(agent) 뒤에
     occupancy_vector(self)를 concat.
   - occupancy_vector(env): 현재 점유된 타깃칸을 1/0 벡터로 반환.

2) 래퍼(monkeypatch) — 기존 스크립트의 "env 클래스만" 바꿔치기:
   - comm_train_battery_occ.py : comm_train_battery.BatteryShapeFormationEnv 를
       BatteryOccupancyShapeFormationEnv 로 rebind 후 comm_train_battery.main() 실행.
       (make_env와 probe가 모듈 전역 이름을 참조하므로 두 곳 모두 점유 env 사용)
   - comm_eval_battery_occ.py  : 동일 방식으로 comm_eval_battery.main() 실행.
   - comm_eval_strict_occ.py   : comm_eval_strict 의 Battery/Shape 두 클래스 모두
       점유판으로 rebind (strict 평가의 충돌/배터리 즉시종료 + 빨강/CRASH 연출 그대로).
   - wind_sweep_battery_occ.py : wind_sweep_battery가 쓰는 comm_eval_battery의
       env 클래스를 점유판으로 rebind 후 wind_sweep_battery.main() 실행.
   * 래퍼는 "env 클래스 한 줄 교체"라 학습/평가 로직 중복이 전혀 없음.

3) colab_runner/colab_runner_occupancy.ipynb
   - colab_runner_final.ipynb를 본떠 만든 새 러너. 차이점:
     * 학습: comm_train_battery_occ.py / 평가: comm_eval_battery_occ.py /
       sweep: wind_sweep_battery_occ.py 사용.
     * Smoke test 셀이 점유 env의 obs_dim = base + n_agents 임을 검증.
     * 산출물 경로에 _occ 접미사 → 비-점유 실험과 분리(섞이면 obs_dim 불일치).
     * 보상 개선값을 기본 반영: ASSIGNED_TARGET_REWARD 0.1->0.4,
       ENT_COEF 0.01->0.02, COVERAGE_STEP_REWARD 0.01(신규) 전달.

[함께 묶인 보상 개선 — 별도 작업분, REWARD_CHANGES.txt 참고]
--------------------------------------------------------------------------------
이 러너는 앞서 적용한 보상 개선(상시 커버리지 보상 coverage_step_reward,
assigned_target_reward↑, ent_coef↑)을 셀 8 설정/명령에 함께 반영함. 점유 관측 +

[검증/주의]
--------------------------------------------------------------------------------
- 로컬에선 torch 미설치라 실행 불가. 문법 검사(py_compile)는 전체 통과.
- 점유 ckpt를 비-점유 eval(comm_eval_battery.py 등)에 넣으면 obs_dim 불일치로
  load 실패(반대도 동일). 반드시 _occ 스크립트끼리 짝지어 사용.
- 기대 효과: 빈칸을 직접 관측 → "빈칸으로 가기/유지" 학습 용이 → 교착(freeze) 감소.
  비-점유(final) vs 점유(이 러너)를 같은 시퀀스로 학습해 GIF/성공률 비교 권장.

[강화학습 정당성 관련]
--------------------------------------------------------------------------------
- 배정(헝가리안)은 기존에도 "목표 칸"만 고정으로 주는 스캐폴딩이고, "어떻게
  도달/조정/충돌회피" 하느냐는 여전히 학습된 정책의 몫.
- 본 변경은 정답을 떠먹이지 않고 "관측 정보(빈칸 여부)"만 보강 → 조정 판단을
  정책 안에 유지. (동적 재배정 대비, "RL 의미 없다" 비판에 더 방어적)
- comm_fail_prob/바람을 켜고 평가하면 "고전 솔버 대비 RL이 robust"라는 근거를
  직접 만들 수 있음(점유 신호는 전역이지만, 충돌회피·바람보정·부분관측 하의
  제어는 여전히 비자명).
